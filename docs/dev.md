# WhatInput 开发文档

## 当前确定的需求

- Windows 10/11 本地工具，简体中文界面、系统托盘、自启、单实例。
- 交付一个 `WhatInput.exe`，使用 Qt Widgets 原生界面，单进程多线程。移除 WebEngine、WebChannel、网页资源和独立统计窗口程序。
- 所有键盘、所有鼠标、所有手柄分别合并；临时设备状态独立维护，避免两把键盘同时按相同键漏计。
- 按软件及 UTC 秒聚合次数，支持本地秒级时间筛选，包含起点、不包含终点。
- 内存接收输入，界面可见时约每 100 毫秒刷新，默认每 60 秒向 SQLite 提交增量。
- 保存间隔可在设置中修改为 1～3600 秒；设置持久化于运行目录 `config/settings.json`。
- 数据永久保留，支持导出 CSV、二次确认清空；不提供暂停功能。
- 所有运行数据、设置、日志、临时文件置于 EXE 所在目录，不使用 AppData。

## 线程与职责

| 线程 | 职责 |
| --- | --- |
| Qt 主线程 | 托盘、Widgets、筛选、表格与柱状图、设置、用户操作 |
| Raw Input 线程 | 隐藏 Win32 窗口及消息循环、键鼠状态、设备变化、电源通知 |
| XInput 线程 | 已连接插槽约 8 ms 轮询、空插槽约 1 s 探测、按键边沿及扳机迟滞 |
| 存储/查询线程 | 唯一 SQLite 写入连接、历史查询、当前视图聚合缓存、CSV 导出 |

采集线程只更新内存聚合，不访问 SQLite 或界面对象。跨线程共享缓冲区由互斥锁保护。存储/查询线程通过 Qt 排队信号向主线程交付不可变视图结果，界面以请求编号丢弃过期查询。

## 输入规则

键盘按设备的扫描码及 E0/E1 标志识别，只统计松开到按下；区分左右修饰键、主 Enter 与小键盘 Enter。未知键显示代码。两台设备相同键的状态独立，计数合并到键盘类别。

鼠标统计左、右、中、侧键 1/2；垂直与水平滚轮仍按方向单列，高精度余量按设备、轴及方向累计到 120 后视为有效滚动。有效滚动使用所有鼠标共用的滚动 1000 毫秒限频：首次加 1 后，1000 毫秒内其他方向、轴或设备的滚动均不再累计，也不延后补计。连续滚动最多每秒计一次，方向和软件归属取本次被接受的滚动。限频使用单调时钟，不受系统时间调整影响。不保存指针移动。

手柄支持 XInput 兼容设备，统计按钮、十字键、摇杆按压和左右扳机；不统计摇杆轴。扳机按下阈值 160，释放阈值 96。首次连接、重连和唤醒先取基线，已按住的按钮不额外计数。所有插槽最终合并到手柄类别。

软件归属：键盘和手柄按前台软件，鼠标按指针目标窗口。已识别的桌面、任务栏、开始菜单等归“Windows 系统”，文件资源管理器单列。无法识别的归“未知应用”。软件显示名称实时读取当前窗口标题，无标题时显示进程名，不缓存或保存窗口标题，不记录输入文本。统计身份仍按进程标识；对宿主进程窗口尝试识别实际内容子窗口。

## 内存、实时视图与保存

维护三个不同用途的数据对象：

1. **活动增量**：按“秒 × 软件 × 类别 × 控件”聚合，接收新输入。
2. **待提交批次**：保存时从活动缓冲交换得到，提交期间新增输入进入新缓冲。失败时保留批次和原批次 ID。
3. **当前视图变化**：仅在窗口可见且未最小化时累计，用于实时更新已查询的视图；不代表需要额外写入数据库。

切换筛选时，由存储线程查询已提交历史，并合并该时点的待提交批次及活动增量，形成新的视图基线。采样基线后新输入进入视图变化缓冲，后续在刷新时应用一次。

数据库提交不改变逻辑上的累计次数，所以保存成功时不再次把批次加到视图中。存储与历史查询在同一线程串行执行，避免读到半提交状态；输入线程在查询和提交期间继续更新内存。隐藏窗口时关闭视图变化追踪，重新打开时重建完整视图。

同样的筛选条件用于总次数、按键排行、软件排行、小时图和 CSV；CSV 包含尚未保存的计数。占比分母为当前筛选区间的全部次数。

## SQLite

数据库：`data/whatinput.sqlite3`，WAL、`synchronous=FULL`，存储版本 4。鼠标另有 `mouse_screens` 配置表和 `mouse_positions` 坐标聚合表，位置明细和普通计数在同一批次事务内提交；键盘与手柄的计数结构不变。

- `devices` 保存三个类别身份：`category:keyboard`、`category:mouse`、`category:gamepad`。
- `controls` 保存控件代码及显示名，控件代码含设备类别前缀。
- `apps` 保存应用身份及名称，避免将 PID 用作长期身份。
- `counts` 主键为 `(second_utc, device_id, control_id, app_id)`，保存 64 位 `press_count`。
- `batches` 保存批次 ID，批次标记与 UPSERT 增量在同一事务内提交。

对同一批次重试不会重复增加。提交结果不明确时重新打开数据库并查询批次标记；标记存在即视为已提交，不能再将其作为未提交增量叠加。

正常每 60 秒保存，有用户设置时按新值重新计时。立即保存和正常退出会提前提交；写入失败保留批次，约 5 秒后重试，并记录错误日志。日志按大小轮转。

按照 `AGENTS.md`，存储格式变动直接删除旧库及 WAL/SHM，不实现同步、迁移或兼容读取。部署脚本先正常退出相关程序、确认目标在当前工作区发布目录内，再删除旧库。构建不会运行应用以创建新库；新程序第一次由用户启动时创建。

## 关闭、清空与退出

- 关闭统计窗口：隐藏窗口，停止 100 ms 刷新，继续采集和周期保存。
- 清空：存储线程隔离清空点之前的活动增量，串行删除数据库记录；成功后丢弃旧活动增量和待提交批次，清空之后的新输入保留。删除失败时将隔离增量合回。
- 退出：先停止 Raw Input/XInput 生产者，再要求存储线程排空并保存。保存失败时保留待提交数据，用户可重试或明确丢弃后退出。
- 休眠/系统会话结束通知：请求提前保存，强制终止和断电仍无法保证内存数据持久化。

## 界面

原生窗口提供：今天、昨天、最近 7 天、全部；秒级起止时间；软件和设备类型筛选；小时活动柱；软件排行；按键名称、类型、次数、占比；点击小时下钻及返回；总次数、待保存次数、最近落盘时间和刷新时间；设置、立即保存、CSV 导出、清空历史。

状态明确区分无输入、读取失败、保存失败及采集故障。读取失败保留旧视图时标注未更新。所有数据更新必须发生在主线程控件中。

## 构建与部署

`packaging/build.cmd` 执行 CMake 配置、单个 WhatInput 目标构建、安装到 `build/package`、windeployqt、更新 `release`。仅依赖 Qt Widgets/Qt Base，不再需要 WebEngine。

`packaging/deploy.ps1` 清理旧应用运行组件，保留 config/logs/exports 等用户目录。本次用户明确要求保留键盘和手柄历史，因此 v3→v4 不删除整个数据库：首次启动时通过事务删除旧鼠标计数、创建位置表并更新版本，再次启动不重复清除。构建不运行任何测试或应用自检。

## 当前验证约束

只有用户明确允许才能测试。未获允许时不执行单元测试、集成测试、窗口操作验证、硬件复测或资源测量；构建脚本不运行测试。旧测试源属于历史版本，未用于验证本次实现。

本次状态见 `docs/validation.md`。首版原生界面的实际交互、多个输入同时发生、保存期间刷新、异常写入恢复、退出重试和长时间运行均待用户允许后验证。
