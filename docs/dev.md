# WhatInput 第一版开发文档

> 2026-11-03 需求修订：取消具体设备统计，所有键盘、所有鼠标、所有手柄分别统一累计；取消单设备筛选、设备在线状态展示和长期硬件身份管理。采集层仍按临时设备句柄/XInput 插槽分别维护边沿及滚轮余量，避免多设备同时输入漏计。持久化仅使用三个类别身份，旧数据按“秒 × 软件 × 类别 × 控件”求和迁移，并保留升级前备份。以下早期设计中涉及具体设备身份、单设备查询及插槽展示的条款由本修订替代。

## 1. 文档范围与目标

WhatInput 是面向 Windows 10/11 的轻量级本地输入统计工具。登录后后台常驻托盘，统计键盘、鼠标和 XInput 手柄的按键次数；用户按需打开简体中文统计窗口，查看累计次数或指定时间段的按键排行。

第一版优先打通“后台采集 → SQLite 持久化 → 指定时段排行”，随后完善界面和部署。统计精确到秒，只保存聚合次数，不保存输入文本、按键顺序、逐次事件时间戳或鼠标轨迹。无本地 HTTP 服务、云服务或在线前端资源。

本文件最初编写时工作区为空。目前已实现可构建初版，实际构建与验证结果以 `docs/validation.md` 为准；本文中的计划不自动代表所有实机验收已完成。

## 2. 技术基线与环境检查

- 语言与构建：C++20、CMake，首版以 Windows x64 Release 为交付目标。
- 采集器：Win32 API、Raw Input、XInput、SQLite，不链接 Qt WebEngine。
- 统计窗口：Qt 6 Widgets、WebEngineWidgets、WebChannel；SQLite 只读连接。
- 页面：随程序打包的 HTML、CSS、JavaScript，不依赖 CDN、远程字体或在线脚本。
- SQLite：建议通过固定版本的官方 amalgamation 编译为内部库，两个程序共享数据库访问封装，避免依赖部署遗漏的 SQL 驱动。

开始开发前检查 Visual Studio/MSVC、Windows SDK、CMake、Ninja、Qt 安装目录及 Qt WebEngine/WebChannel 模块。选择同时满足 Qt 对编译器、CMake 和目标 Windows 版本要求的组合，再将准确版本写入构建说明与依赖锁定清单；不得假定系统已经安装某一版本。

依赖应固定版本及来源，记录许可证、下载校验值和更新方式。Qt、应用和运行库必须采用相同架构及兼容 ABI。Windows 10 的最低具体版本须根据最终选择的 Qt 支持范围明确，并在目标机器验证。

## 3. 进程架构

```text
键盘/鼠标 → Raw Input → 采集状态机 ─┐
                                  ├→ 内存分钟增量 → 写入线程 → SQLite WAL
手柄 → XInput 轮询 → 按钮状态机 ────┘                         ↑
                                                            │ 只读
原生托盘 → 启动/激活 WhatInputStats → 本地页面 ↔ QWebChannel ↔ 查询线程
```

### 3.1 WhatInput.exe

- 每用户单实例后台进程，使用带用户标识的命名互斥量；第二次启动时请求已有实例打开统计窗口，然后退出。
- 创建隐藏的普通顶层窗口，运行 Win32 消息循环，处理 Raw Input、设备变化、电源通知和托盘消息。
- 托盘菜单：“打开统计”“开机自启”“退出”。不提供暂停功能，停止统计需退出采集器。资源管理器重启后恢复托盘图标。
- 使用当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 设置开机自启；保存带引号的可执行文件绝对路径，无需管理员权限。菜单勾选状态以注册表实际配置为准。
- 独占数据库写入职责，状态变化和元数据更新也通过写入线程处理。
- 状态 IPC 使用限当前用户访问的命名管道，提供运行状态、最后成功提交时间和写入错误摘要。IPC 不可用时界面明确显示“采集器未运行或状态不可用”。

### 3.2 WhatInputStats.exe

- 独立单实例统计进程，通过每用户 IPC 请求已有窗口显示、还原并激活；处理 Windows 前台激活限制，失败时闪烁任务栏提示。
- 加载 `qrc:/web/index.html` 等内嵌资源，注册最小化 QWebChannel 查询桥接对象。
- 关闭窗口后退出进程并释放 WebEngine 子进程，采集器继续运行。
- 数据库查询在工作线程执行，每个线程使用自己的只读连接，避免阻塞 UI。
- 禁止页面外部导航、远程网络请求和不需要的下载能力；不暴露任意 SQL、任意文件访问或命令执行接口。
- 窗口显示期间约每 5 秒刷新，允许一个写入周期的延迟。后台错误或数据库锁定时不进行无限紧密重试。

## 4. 输入模型与设备身份

### 4.0 软件归属（新增确定需求）

每次计数同时确定软件归属，按“UTC 秒 × 软件 × 设备 × 控件”聚合。软件标识不能采用易复用的 PID；桌面程序使用规范化可执行路径，打包应用优先使用稳定的包/应用身份。软件名称和身份另表保存，不记录窗口标题、文档名、网址或输入文本。

建议归属口径：键盘按下及手柄按钮变化归入当时前台软件；鼠标按下归入当时点击目标窗口所属软件，滚轮按指针目标窗口归属。桌面、任务栏、开始菜单等系统 Shell 界面合并到“Windows 系统”；文件资源管理器的文件窗口作为“文件资源管理器”单列，不能仅看到 explorer.exe 就全部归入系统。无法可靠解析的对象显示“未知应用”，不能冒充系统。

此处归属是操作上下文，不代表能证明哪个软件实际消费了输入；后台接收手柄、全局热键、鼠标捕获、覆盖层及窗口切换瞬间存在边界。实现时结合前台切换通知与输入时目标快照，缓存进程身份解析，避免在输入路径做磁盘查询；临时的事件上下文不得作为逐次历史落盘。Raw Input 本身不提供最终接收软件身份，点击归属需要额外窗口命中测试，必要时用鼠标钩子仅补充上下文而不重复计数。不得承诺仅用延迟后的前台窗口查询就能准确定位点击目标。

增加按软件的总次数排行，以及软件筛选下的按键排行和活动图。浏览器默认按浏览器软件统计，不区分网站或标签页。手柄按前台软件归属、滚轮按指针目标归属及文件资源管理器单列属于当前建议口径，需求讨论时需向用户说明。

### 4.1 设备标识

Raw Input 的临时 `HANDLE` 只用于本次进程内索引，不得直接写成长期设备 ID。通过设备接口路径、PnP 信息、可用序列号等生成规范化设备标识，再映射至数据库内部 ID。两把同时连接的键盘必须有不同 ID。

没有可靠序列号的同型号设备可能无法跨 USB 端口保持身份：保持接口路径级区分，并在文档说明更换端口可能产生新设备；不可仅按 VID/PID 合并。设备名为空时提供可读回退名和短标识。历史设备拔出后仍保留，可继续查询。

设备接入/移除后自动更新在线状态及设备筛选列表，无需重启；界面在下一次刷新同步。启动时重新枚举设备。重连优先匹配序列号及对应接口信息、可信 PnP 身份，再回退到接口路径；不得将复合设备的不同控件接口或两台同型号设备错误合并。有稳定唯一身份时复用历史 ID；缺少稳定身份或连接方式变化时不保证自动识别为原设备。原始设备到长期身份的映射必须持久化。

XInput 以插槽 0–3 为统计身份，显示“手柄 1（插槽 0）”等名称。界面说明重连后插槽可能变化，相同插槽在不同时间可能对应不同实体手柄。

### 4.2 键盘

- 注册 Raw Input 键盘设备，使用后台接收和设备变化通知标志；其他应用或游戏处于前台时继续接收系统实际提供的输入。
- 键位 ID 由物理扫描码和 E0/E1 扩展标志组成，例如 `kbd:sc:001C:e0`；按设备维护按下集合。
- 仅在未按下到按下的转换时加一；重复 make 消息不增加次数，break 消息清除状态。
- 区分左右 Ctrl、左右 Alt、主 Enter 和小键盘 Enter；处理 Shift、Pause、Print Screen 等特殊扫描码序列，过滤文档定义的伪消息，防止重复计数。
- 控件 ID 不随键盘布局变化。显示名使用明确映射及 Windows 名称接口回退，未知键显示扫描码及扩展标志；不使用文本翻译接口，不重建输入字符。
- 扫描码缺失等特殊上报采用明确、可测试的回退 ID，保留可辨识代码，不与正常扫描码键静默合并。

### 4.3 鼠标

- 按设备区分左键、中键、右键、侧键 1、侧键 2，只统计按下转换。
- 垂直滚轮分为向上、向下；水平滚轮分为向左、向右。标准 `WHEEL_DELTA = 120` 对应一次。
- 每个设备、滚轮轴和方向分别保留不足一格的余量。例如同方向四次 +30 计一次；正负方向余量不相互抵消。该规则固定写入测试，避免实现间歧义。
- 中键点击与滚轮始终使用不同 control ID；忽略移动坐标。

### 4.4 XInput 手柄

- 首版支持 XInput 兼容设备，不承诺支持所有 HID/DirectInput 手柄。
- 已连接插槽初始约每 8 毫秒轮询，空插槽约每 1 秒探测；轮询在独立线程完成，不阻塞窗口消息或数据库操作。
- 按 `XINPUT_GAMEPAD` 按钮位的上升沿统计面键、肩键、菜单键、摇杆按压及十字键。摇杆轴移动不计数，未由 XInput 提供的按钮不承诺支持。
- 扳机使用迟滞状态机，初始建议按下阈值 160、释放阈值 96（范围 0–255）：释放态达到按下阈值计一次；按下态降至释放阈值才释放；中间区域保持状态。
- 首次连接、重连、休眠唤醒时先读取基线，不将当前已按下按钮计为新点击。扳机初始值处于迟滞区时按抑制态处理，必须先释放再允许计数。

### 4.5 断开、休眠与退出

- 不提供用户暂停入口，也不保存暂停设置；启动即统计，退出即停止。
- 设备断开时清除该设备的临时按下状态和滚轮余量，不删除历史数据。
- 休眠前请求提交并进入抑制状态；唤醒时重建设备映射并重新同步，轮询手柄的首次状态仅作为基线。
- Raw Input 不提供完整的逐设备当前键盘状态快照。对已知按住的键保留“等待释放”状态；新设备或唤醒后的首个 make 若无法判断是否为重复，只能采用保守抑制并在验证报告说明可能漏掉首次点击的边界，不得宣称完美恢复未知状态。
- 正常退出先停止输入生产者，再封存并提交剩余数据，最后释放数据库和托盘。写入持续失败时记录错误并明确报告未保存数量，不能把失败当作成功退出提交。

## 5. 数据库与持久化

所有由应用控制的运行文件和缓存统一放在程序运行目录下，不使用 AppData。这里的“运行目录”固定指两个 EXE 所在目录，而非启动进程的当前工作目录；两个程序必须共享该根目录。

建议布局：

```text
WhatInput/
  WhatInput.exe
  WhatInputStats.exe
  data/whatinput.sqlite3   # 包括同目录的 WAL、SHM 文件
  config/settings.json
  logs/                   # 轮转诊断日志
  cache/webengine/         # WebEngine 缓存
  data/webengine/          # WebEngine profile 持久化数据
  temp/                   # 应用及子进程可配置的临时文件
```

初始化 Qt WebEngine 前显式配置专用 profile 的缓存和持久化目录，并设置应用可控制的临时目录，避免默认 profile 或路径回退写入 AppData。设置、导出文件默认位置及应用主动生成的诊断文件均位于此根目录。日志不得包含逐次按键事件、文本或按键序列。操作系统自行产生的系统诊断或驱动文件不属于应用可控制范围，不能承诺改变其位置。

启动时检查运行目录可写；不可写则明确报错并停止采集，不静默回退到 AppData，不自动请求管理员权限。推荐解压到当前用户可写的目录，避免 Program Files 等受保护位置。目录迁移或备份前正常退出两个程序，确保待写数据提交；迁移整个目录可带走历史与设置。首版按单 Windows 用户使用设计，不支持不同用户同时写入同一发布目录。

建议基础结构：

```sql
CREATE TABLE devices (
    device_id TEXT PRIMARY KEY,
    device_type TEXT NOT NULL CHECK(device_type IN ('keyboard','mouse','gamepad')),
    display_name TEXT NOT NULL
);
CREATE TABLE controls (
    control_id TEXT PRIMARY KEY,
    device_type TEXT NOT NULL,
    display_name TEXT NOT NULL
);
CREATE TABLE applications (
    app_id INTEGER PRIMARY KEY,
    identity TEXT NOT NULL UNIQUE,
    display_name TEXT NOT NULL
);
CREATE TABLE second_counts (
    second_utc INTEGER NOT NULL,
    app_id INTEGER NOT NULL REFERENCES applications(app_id),
    device_id TEXT NOT NULL REFERENCES devices(device_id),
    control_id TEXT NOT NULL REFERENCES controls(control_id),
    press_count INTEGER NOT NULL CHECK(press_count >= 0),
    PRIMARY KEY (second_utc, device_id, control_id, app_id)
) WITHOUT ROWID;
CREATE TABLE committed_batches (
    batch_id TEXT PRIMARY KEY
);
```

`second_utc` 为 Unix UTC 秒时间戳，计数使用 64 位整数。仅在存在活动时创建分钟记录，不为零活动补表。通过 `PRAGMA user_version` 管理迁移；仅采集器执行迁移，界面遇到不兼容版本显示明确提示。

新增软件维度后，核心主键由原来的三列扩展为四列。历史永久保留，不自动过期删除。实际实现建议为设备和控件采用紧凑整数代理键，长路径及身份字符串仅保存在维表，避免每条分钟记录重复保存。

时间按秒聚合，不保存逐次事件及毫秒时间。例：同一秒、同软件、所有键盘的 W 合计按 3 次，仅一行 count=3。空间取决于活跃组合数。容量估算必须注明假设，并用实际数据库验证；不能将估算作为实测结论。

### 5.0 导出与清空（新增确定需求）

- 支持将当前筛选排行和秒级聚合明细导出 CSV，包含软件、设备、按键、次数，明细另带 UTC 秒和本地时间偏移。写入运行目录的 `exports/`，妥善处理 CSV 转义及公式注入，中文编码兼容常用表格软件。
- 支持清空全部历史，操作前二次确认；首版不默认提供按软件或时段删除。清空不改变自启配置。
- 统计窗口仍不写数据库：经限当前用户的 IPC 请求采集器执行清空。写入线程串行处理清空命令，设定明确的内存批次代际边界，丢弃清空点之前的待写计数，避免重试批次让已清空记录复活；清空点之后输入继续累计，设备按下状态保留以避免长按被重计。
- 清空失败时返回错误并保持一致状态；采集器未运行时要求先启动采集器执行操作。导出使用只读一致快照；明确数据截至最后提交周期。

### 5.1 写入协议

1. 输入处理路径仅更新受短临界区保护的内存分钟增量；设备名称解析、日志和数据库 IO 均不在计数热路径执行。
2. 约每 5 秒交换活动缓冲区，形成不可变批次，分配随机唯一 `batch_id`。提交期间新输入写入新的活动缓冲区。
3. 单写入线程执行 `BEGIN IMMEDIATE`，先插入批次 ID。若该 ID 已存在，则本批次已经提交，不再增加计数。
4. 新批次在同一事务内补齐软件/设备/控件元数据，使用 UPSERT 将增量累加到已有分钟记录，随后提交。批次标记和计数必须原子提交。
5. 成功后释放批次；失败则保留原批次及原 ID，退避重试。COMMIT 结果不确定时，重新连接后检查相同 ID，禁止为重试生成新 ID。
6. 同一分钟重启后使用新批次 ID，并在已存在分钟值上累加，不能用新进程内累计值覆盖历史值。

事务内出现错误必须回滚或重新建立连接后核验批次。明确已提交且不会再重试的批次标记可由写入线程在后续事务清理；重启后若没有持久化待重试队列，可清理旧标记。未来引入持久化队列时必须重新定义标记清理协议。

启用 WAL、外键约束、合理的 busy timeout；首版优先使用 `synchronous=FULL`，实际性能以测量决定。读取连接启用只读打开和 `query_only`，不得修改 journal mode 或建表。WAL 侧文件与主数据库处于同目录，部署和备份说明不可遗漏一致性要求。

### 5.2 故障边界

数据库忙、磁盘满或权限错误时保留待写聚合并展示可诊断错误，包括 SQLite 错误码和最后成功提交时间。对长期失败设置明确内存上限：达到上限后进入采集故障状态并告警，不静默丢弃待写数据。重复批次去重仅保证数据库提交不多算，不等于内存数据具备崩溃持久性。

正常退出要求提交剩余数据；进程被强制终止、系统崩溃或断电可能丢失尚未提交的内存增量，正常情况下约为一个写入周期，持续写入失败时可能更长。若要求异常退出零丢失，需要额外设计仅含聚合数据的本地持久化队列，不在首版默认承诺内。

## 6. 查询接口与时间语义

- 所有筛选采用 `[start, end)`，包含起点、不包含终点。自定义时间输入精确到秒，要求起点小于终点。
- 页面提交本地时间，由 C++ 明确转换为 UTC 秒。夏令时不存在的本地时间应提示修正，重复时间应允许选择偏移量，不依赖 JavaScript 隐式猜测。
- “今天”是本地今日零点至明日零点；“昨天”是昨日零点至今日零点；“最近 7 天”是含今天的七个本地自然日；“全部”不设置时间边界。实际查询范围在页面明确显示。
- 总排行按所选范围内 `SUM(press_count)` 降序排列。筛选支持全部设备、设备类型、具体设备，选择具体设备后校验其类型一致性。
- 默认同类设备合并，按 `device_type + control_id` 分组，并允许选择单个设备。键盘、鼠标和手柄分别展示，禁止仅按显示名称合并。支持全部软件和单软件筛选，图表、排行、占比使用相同软件条件。
- 占比以当前筛选范围全部计数为分母，不能以可见前 N 行或单页计数为分母。零分母显示空态。

基本排行查询：

```sql
SELECT m.device_id, m.control_id, SUM(m.press_count) AS total
FROM second_counts AS m
JOIN devices AS d ON d.device_id = m.device_id
WHERE m.second_utc >= :start_second
  AND m.second_utc < :end_second
  -- 软件、设备及类型条件由固定查询分支追加，值均参数绑定
GROUP BY m.device_id, m.control_id
ORDER BY total DESC, m.device_id, m.control_id;
```

“全部”使用独立无时间条件分支。以查询计划和实际数据量决定是否增加 `(device_id, second_utc, control_id)` 索引，避免过早增加写入开销。

桥接 API 建议包含 `listDevices`、`queryStats`、`getCollectorStatus`。`queryStats` 一次返回时段、柱状图、排行、总数及查询完成时间；总数和排行应来自同一个只读事务快照。响应带 request ID，前端忽略过期响应。64 位计数以十进制字符串传递，避免 JavaScript 整数精度丢失。

小时柱按本地时间边界切分，并携带准确的 UTC 起止值；夏令时重复小时用偏移量区分。20:15–21:45 的首尾柱分别只覆盖 20:15–21:00 和 21:00–21:45。点击柱子时使用柱区间与原始筛选区间的交集，不意外扩大查询范围。

## 7. 简体中文统计面板

- 顶部提供“今天”“昨天”“最近 7 天”“全部”、自定义起止时间、软件、设备类型和设备下拉框。
- 左侧显示活动柱状图；右侧表格显示“按键名称、设备、次数、占比”，默认次数降序，可对稳定次序分页。
- 长时段通过滚动或分级显示避免挤压小时柱；若显示日级聚合，先下钻到该日小时柱，再选择小时排行，禁止把日柱误标为小时。
- 点击小时柱更新右侧排行，突出选中小时并显示“返回原时段”按钮。保留原时段和设备筛选，不以新的小时选择覆盖原范围。
- 显示当前查询区间、查询刷新时间、采集器最后写入时间及采集状态，三种时间或状态含义不能混淆。
- 空态“这个时段没有输入”；采集器退出时显示“采集器未运行”，仍可查看历史；错误态“数据读取失败”，附可操作的重试入口。读取失败保留旧结果时必须标明数据未更新。
- 数据库尚未创建时提示启动采集器，不让只读窗口自动创建空数据库。
- 第一版不实现键盘热力图、输入文本分析、云同步和轨迹记录。

## 9. 验收与可复现测试

自动测试优先使用可注入时钟、规范化输入事件及可替换 XInput 状态源。模拟状态机测试不等同于真实 Raw Input 驱动、游戏或硬件验证。

| 项目 | 方法与预期 |
| --- | --- |
| 点按与长按 | 同设备发送 100 组 make/break，得到 100；一个 make、多个重复 make、一个 break，得到 1 |
| 键位隔离 | 左右 Ctrl/Alt、主 Enter/小键盘 Enter 独立 ID；两设备同时 W 各 1 |
| 鼠标 | 五个按钮各自计数；中键与滚轮分离；四次 +30 得向上 1；跨设备余量不合并 |
| 手柄 | 多插槽独立；按钮位上升沿只加 1；扳机跨迟滞区抖动不重复计数 |
| 恢复基线 | 唤醒或断开重连时已按住不增加；释放再按增加 1 |
| 跨分钟 | 在固定 UTC 秒末尾和下一分钟开头注入事件，得到两个分钟键 |
| 跨午夜 | 使用固定时区构造 23:59 与次日 00:00，分别归入正确本地日期 |
| 排他终点 | 构造 20:14=7、20:15=2、21:44=3、21:45=11；查询 20:15–21:45 得到 5 |
| 同分钟重启 | 第一实例提交 4 后退出，第二实例同分钟提交 6，查询得到 10 |
| 重复提交 | 同批次提交两次只累计一次；模拟提交成功但确认丢失，再次提交仍不多算 |
| 并发到达 | 写入旧批次时产生新输入，旧批次确认后新计数仍存在并可提交 |
| 写入失败 | 注入忙、提交失败及磁盘错误，验证回滚、保留批次、退避和恢复后正确总数 |
| UI 生命周期 | 关闭统计窗口后继续输入，再打开可见新增数据；重复打开只有一个统计窗口 |
| 空态与错误 | 无数据、采集故障、读取失败、采集器未运行分别展示正确状态 |
| 时间与合并 | 验证 DST 重复/缺失小时、局部小时下钻、跨类型同名按钮不合并及占比分母 |
| 软件归属 | 同一分钟在 A、B 软件分别输入，分软件总数与全局相符；从 A 点击桌面归入 Windows 系统；资源管理器文件窗口独立 |
| 热插拔 | 在线状态自动刷新；稳定身份重连沿用历史；无序列号换端口不错误合并 |
| 导出与清空 | CSV 与筛选结果相符；清空时存在待写及重试批次也不恢复旧数据；清空后继续统计 |

实际输入实机复测：准备空测试数据库或记录前后基线；按 W 100 次，再长按 W；分别测试修饰键、两个 Enter、侧键和滚轮。等待至少一个写入周期后查询相应区间，与预期差值比较。不要将 SendInput 测试直接标记为硬件 Raw Input 验证。

有第二把键盘时同时按 W，核对设备独立排行；有手柄时按住按钮进行拔插和休眠唤醒，再释放重按。没有硬件的项目标记“自动模型已验证／实机待验证”，不能标记整体通过。

## 10. Release 构建与部署计划

以下为计划中的命令模板，须在实现相应 CMake 目标和安装规则后执行，并以实际可用 Qt 路径替换变量：

```powershell
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="<Qt安装目录>/<版本>/msvc2022_64"
cmake --build build/release --parallel
ctest --test-dir build/release --output-on-failure
cmake --install build/release --prefix dist/WhatInput
& "<Qt安装目录>/<版本>/msvc2022_64/bin/windeployqt.exe" --release --dir dist/WhatInput dist/WhatInput/WhatInputStats.exe
```

在匹配所选 Qt 编译器的开发者终端运行。目录中的 `msvc2022_64` 只是示例，不表示已选定该工具链。部署脚本应采用所选 Qt 版本支持的部署方式，检查日志和实际输出，不手工猜测 WebEngine 运行文件位置。

发布目录必须包含两个 EXE、Qt DLL、平台插件、`QtWebEngineProcess.exe`、WebEngine resources/ICU 数据及 locales 等实际版本所需文件，并按 Qt 预期目录布局保存。内嵌页面通过 qrc 加载。根据工具链部署匹配的 VC++ 运行库，并附上第三方许可证。

发布验证从 `dist/WhatInput` 启动，且另测工作目录不等于程序目录的情况；在无开发 Qt PATH 的环境和干净目标机器上检查页面、WebChannel、数据库读写、中文显示及日志。验证统计窗口关闭后其 WebEngine 子进程退出，后台 EXE 的链接依赖及运行模块中不含 Qt WebEngine。

采集器通过自身可执行文件所在目录定位统计程序，不依赖当前工作目录。发布目录迁移后重新配置自启，避免注册表仍指向旧位置。

## 11. 实际验证与资源测量报告要求

实现完成后在 `docs/validation.md` 记录提交版本、Windows 版本、CPU、内存、工具链、Qt/SQLite 版本、构建命令、测试数量与结果，以及部署验证的具体机器。

轻量程度以关闭统计窗口后的采集器单独常驻为准。至少分别测量：无手柄空闲、连接手柄空闲、持续键鼠输入、手柄持续活动。每个场景预热后建议采样 10 分钟，记录 CPU 平均值和峰值、Private Bytes、Working Set、线程/句柄数及数据库增量。CPU 百分比要说明是单核占比还是全机归一化；同时记录 XInput 轮询配置。

另记录打开统计窗口的内存增量和关闭后的进程释放情况，不把 UI 内存计入后台常驻结论。检查 24 小时运行时内存、句柄和数据库增长；无持续运行条件时明确标记待验证并给出复测命令或采样步骤。

最终报告严格分为“自动验证”“实机验证”“待验证”：未执行构建不得写构建成功，模拟设备不得写真实硬件通过，未测量不得给出推测的 CPU/内存数字。文档编写阶段以上构建、测试与测量均尚未执行。
