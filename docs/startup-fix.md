# 编译成功后启动崩溃的修复（2026-11-04）

## 检查结果

当前 `window.cpp` 与 `window.h` 中仍包含首页今日统计、五个一级菜单、历史时间筛选、排行、活动图与活跃时段列表，未发现这些功能因合并而缺失。保留当前未提交修改，没有执行 Git 回退或覆盖用户代码。

本机发现构建依赖异常：

- MSVC 的 `/showIncludes` 前缀在 CMake/Ninja 规则中出现乱码。
- Ninja 元数据表明 `main.cpp.obj` 的头文件依赖数量为 0。
- `main.cpp.obj` 原编译时间为 00:44:05，而窗口头文件于 14:52:29 更新，窗口实现于 14:53:58 重新编译；入口对象仍旧。
- Windows 应用事件记录了启动时 `Qt6Core.dll` 的 `0xc0000005` 崩溃。

窗口对象由 `main.cpp` 分配。窗口类成员变化后，入口仍使用旧的对象大小而构造函数使用新布局，会导致越界写入；仅重新链接无法修正这种新旧对象混用。

## 修改

`packaging/build.cmd` 增加 `cmake --build ... --clean-first`，每次构建先清理再完整编译，避免本机头文件依赖识别异常留下旧对象。该措施不改变输入采集、数据库或窗口功能；代价是增量构建速度降低。没有修改生成的 Ninja 规则或编译器缓存。
