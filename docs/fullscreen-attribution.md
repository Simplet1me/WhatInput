# 全屏程序的软件归属修复

## 2026-11-04 实机对照结论：权限不一致

本节取代下方早期未确认的推测。本次用户明确授权了该故障的测试。

| 条件 | 观察 |
| --- | --- |
| 普通权限 WhatInput + 普通窗口 | Raw Input 与低级钩子均收到键鼠消息；对照键盘按下／松开各 2 次 |
| 普通权限 WhatInput + 管理员权限 LOL | 切入对局后无后续正常按下消息；进程识别和 Raw Input 注册正常 |
| 管理员权限 WhatInput + 管理员权限 LOL | 两条通道均恢复；30 秒内游戏前台 Raw Input 键盘按下消息 199、松开 40，鼠标按下／松开各 59；正式统计为键盘 41、鼠标 59（键盘自动重复不累计） |

结论限定于本机这次训练营现场：同等管理员权限恢复了原有 Raw Input 采集，无需将低级钩子作为正式采集后端。不能由此推导其他游戏或机器的反作弊兼容性。

操作方法：从托盘退出已有 WhatInput，再右键 `release/WhatInput.exe` 选择“以管理员身份运行”，接受 UAC。已有普通权限实例必须先退出，否则单实例逻辑只会激活旧实例。当前 HKCU Run 开机自启不保证管理员权限，需要在玩管理员权限游戏前手动重新启动。

诊断模式的低级钩子仅累计消息数量，始终放行消息，不向正式计数写入；30 秒后自动卸载，正常 Raw Input 采集继续。未修改游戏、模拟输入、注入代码、读取游戏内存或调整反作弊。两轮关键快照保存在 `build/lol-diagnostic-normal.json`、`build/lol-diagnostic-elevated.json`，运行目录仍只保留最新健康快照。

额外修正部署脚本：无法读取正在运行的 WhatInput 路径时，停止部署并提示退出，避免跳过该实例后部分删除发布依赖。

## 后续现场诊断：修复未解决 LOL 对局输入缺失

用户许可被动诊断后，使用 `--capture-diagnostics` 输出累计健康快照到运行目录 `logs/capture-diagnostics.json`。该模式只保留最新快照，不记录逐次事件、按键内容或轨迹；后续版本限定为 30 秒自动停止输出，正常采集继续。

本次观察：前台 PID 64412 能正确识别为 `league of legends.exe`，键鼠注册均指向采集窗口，包含 `RIDEV_INPUTSINK`，注册和读取错误均为 0，未处于休眠。游戏前台的一个快照中，鼠标累计按下 1、松开 0，键盘按下 0、松开 2，计数鼠标 1。用户报告此时游戏内持续操作却不增加；切往其他程序后消息和计数又增加。

因此软件归属不是当前故障的充分解释，需继续诊断后台输入消息为何缺失。尚未确认是游戏独占输入、权限、其他输入组件还是反作弊策略导致；未进行注入、模拟输入、内存读取或驱动操作。不能宣称上一次修复已解决问题。

用户反馈：英雄联盟对局期间全部软件总次数增加，但英雄联盟软件排行不增加。
这说明当前报告主要涉及软件归属，而非完全收不到输入。未进行游戏实测，不能据此确认现场的唯一根因。

## 本次修改

- 键盘和手柄继续按前台窗口所属进程统计。
- 鼠标在前台窗口客户区覆盖整块显示器、且光标位于其客户区时，优先归属该前台窗口。适用于独占全屏和无边框全屏的窗口几何形态，不依赖游戏标题或窗口边框样式。
- 普通窗口及光标移至其他显示器时，继续按光标下目标窗口统计；桌面和任务栏仍归入 Windows 系统。
- 进程完整路径查询失败时，使用 Windows 进程列表中的 EXE 名称作为降级识别，显示“进程路径受限”，而不是将所有此类程序混入未知应用。该查询不获取模块、堆或游戏内存，不申请管理员权限。
- 受限路径结果短期缓存 5 秒；缓存同时核对窗口和 PID。

降级识别无法区分不同目录中的同名 EXE；其排行项与能读取完整路径的排行项分别显示。无法取得进程列表时仍归入未知应用。旧版已归入未知应用的计数无法可靠追溯到游戏，不做猜测性重分配。数据库结构和存储格式未变。

## 待用户许可后的复测

本次仅构建，不执行下列测试：

1. 分别进入游戏窗口、无边框全屏和全屏模式，选择今天、全部软件、全部设备类型，比较游戏前后计数及软件排行。
2. 查看实际对局进程对应项，勿只选择启动器／大厅进程；完整路径不可读时查看带“进程路径受限”的同名 EXE 项。
3. Alt+Tab 切换到其他程序，确认新输入归属切换；多屏环境点击副屏桌面应归入 Windows 系统。
4. 若总次数仍增加但归属错误，记录排行中的实际软件名称（或未知应用）和窗口模式，进一步定位，不直接认定为反作弊拦截。
